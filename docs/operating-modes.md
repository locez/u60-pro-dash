# 连接与性能模式

Web 与机身屏幕使用同一组设备状态和设置接口。飞行模式、应用带宽分配、高铁优化归入移动网络；性能三档归入电源与电池。Web 顶栏、概览和解锁后的机身状态栏提供快捷控制。

## 飞行模式

开启前提示蜂窝数据、通话、短信及经过蜂窝的远程连接将中断；Wi-Fi、USB 与本地管理继续可用。关闭飞行模式直接请求恢复蜂窝射频。

后台使用原厂 `nwinfo_set_mode` 请求进入 `LPM`，B31 实机随后回报 `OFFLINE`（`AT+CFUN?` 为 0）；两种状态均表示射频关闭。恢复使用已有的 `AT+CFUN=1` 路径，避开该固件的 ubus ONLINE 恢复问题。指令完成后还要核对实际射频状态，返回原厂实际值；未确认时返回错误，客户端重新读取状态。不会自动重发写请求或自动重启设备。射频恢复成功与运营商注册、数据连接恢复分别显示，不能仅凭 ONLINE 宣称已经联网。

读取 UCI 状态时，先取得 B31 原厂库使用的 `/tmp/lock/<package>.ucilock` 共享锁，再读取基础配置和增量文件。只锁配置文件本身不足以覆盖原厂的完整提交过程。提交期间增量清空、基础文件尚未替换时，不把原有 ONLINE 或 OFFLINE 当作新状态。遇到锁竞争、固件锁缺失或无法解析的格式，交给原厂 UCI 读取。

B31 恢复时偶尔没有返回完整的 AT `OK` 回执。后台仍在有限时间内读取射频实际状态，确认 ONLINE 才算恢复成功；不因回执缺失就重发命令，也不因收到 `OK` 就跳过状态确认。

开启飞行模式时保留性能档位和应用带宽选择。首页、锁屏和状态栏同步显示飞行状态，蜂窝速率与信号不再显示原先的缓存值。锁屏展示信息，修改操作必须先解锁。

## 性能三档

策略仅针对已识别的 `qcom-cpufreq-hw` CPU 调节接口。读取接口和打开设置页面不写入硬件；首次选择时记录原有频率范围。未识别的驱动、缺失的策略文件或不支持的档位禁用对应控制。

| 档位 | 实际策略 |
| --- | --- |
| 均衡 | `schedutil` 按需调整，使用记录的原有最小与最大频率 |
| 性能 | `performance` 优先处理能力，使用原有频率范围，不超频 |
| 省电 | `conservative`，最大频率取不超过原上限 70% 的可用档位，保留原最小频率 |

B31 样机报告的原始范围为 691200–2208000 kHz，省电上限因此为 1516800 kHz。该比例是本项目的 CPU 策略，不等同于原厂未确认的 `power_saver_mode`，也不承诺固定的网速或续航增幅。高负载时性能档可能增加发热与耗电；省电档可能降低处理及转发能力。

每次操作校验所有 CPU 策略后再写入、回读，最后以 0600 权限原子保存到 `/data/u60-dash/performance.json`。写入或保存失败时恢复操作前的 CPU 设置，并区分回滚已确认与无法确认。后台启动时恢复已保存档位；运行期间不会持续覆盖其他程序的 CPU 设置。外部修改造成偏离时，界面显示所选模式未生效。

温控守护进程和内核保护始终保留。温度保护状态来自 CPU 对应 cooling device 的 `cur_state`，不是根据一个猜测的温度阈值显示。无法取得状态时返回未知。当前仅验证策略读写与回读，整机功耗、吞吐和续航仍需对照测试。

## 应用带宽分配与高铁优化

| 界面选项 | 原厂 QoS 枚举 | 含义 |
| --- | --- | --- |
| 极速 | `Nomal_mode` | 不区分应用优先级，按需使用带宽 |
| 智能 | `Ai_mode` | 原厂自动分配应用优先级 |
| 游戏 | `Game_mode` | 游戏流量优先 |
| 视频 | `Video_mode` | 视频流量优先 |
| 会议 | `Chat_mode` | 会议与网课流量优先 |
| 直播 | `Live_mode` | 直播流量优先 |

这些是原厂带宽分配策略，不修改 CPU 档位。设置通过原厂 `zte_smart_mng_set_qos_mode` 写入，核对 `zwrt_smart_mng.smart_qos.mode` 后才返回成功。具体应用识别与分配效果由固件负责。

高铁优化读取 `zte_nwinfo.sys_info.hst_info`：1 表示工作中，0 表示未触发。飞行模式时显示暂停；缺失或未知值显示未知。目前未发现可验证的手动开关，不提供虚假的启停功能。

## 接口与刷新

| 接口 | 用途 |
| --- | --- |
| `GET /api/device/operating` | 射频、带宽策略、高铁状态及 CPU 档位；各项独立报告可用性 |
| `POST /api/modem/airplane` | `operate_mode` 为 `LPM`、`OFFLINE` 或 `ONLINE` |
| `PUT /api/device/performance` | `profile` 为 `balanced`、`performance` 或 `saving` |
| `PUT /api/modem/bandwidth` | `mode` 为上表对应的 `normal`、`ai`、`game`、`video`、`meeting`、`live` |

全部接口沿用后台认证。`operating` 实时主题按需采样，周期 5 秒；设置后主动通知刷新。屏幕熄屏时停止订阅，未变动的控件不重绘整页。五种语言与浅深主题沿用项目偏好。

## 验证记录

- 省电、性能、均衡依次写入后分别观察 6 秒，CPU governor 与频率范围符合预期，最后恢复均衡。配置保存权限为 0600，后台重新部署后仍按保存的档位恢复。
