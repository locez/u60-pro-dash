# 无线设置保存与确认

Web 与机身共用 `PUT /api/wifi/settings` 和 `PUT /api/wifi/guest`。普通选择自动提交；会重启热点的操作先提示，取消不写入。成功必须通过应用后的实际值核对；后台返回失败原因，界面保留失败提示与待修改内容，不自动重发写请求。

## B31 的 Wi-Fi 7 开关

B31 可在两个频段已经配置 `11beg`、`11bea` 时省略 `wireless.zte_mbb.wifi6_switch`。原有实现把缺失值当作关闭，又因为缺少这个可选字段而选择不存在的旧配置路径，最后忽略写入错误并报告成功。

现在根据父配置节选择保存位置。缺少开关键时，结合两个频段的实际无线模式判断；无法判断时不伪造关闭状态。显式切换通过原厂 `zwrt_wlan set` 同时处理开关、无线模式和带宽格式。

| 选择 | 2.4 GHz | 5 GHz |
| --- | --- | --- |
| Wi-Fi 7 开启 | `11beg`，EHT 带宽 | `11bea`，EHT 带宽 |
| 兼容模式 | `11ng`，HT 带宽 | `11ac`，VHT 带宽 |

切换保留原有带宽数值；两个界面按当前标准提供带宽选项。Web 切换全局标准后立即重读两个频段的表单。开启 MLO 时拒绝直接进入兼容模式，避免留下冲突配置。

固件字段仍称为 `wifi6_switch`，供已有客户端继续使用。开关与客户端实际协商协议分别看待：没有连接 Wi-Fi 7 客户端时，不以带宽设置推断客户端已经使用 Wi-Fi 7。

## 同类保存问题

| 项目 | 修复 |
| --- | --- |
| 发射功率 | 使用原厂 `txpowerpercent`，不再把百分比乘固定数值当作射频功率，也不忽略应用命令失败 |
| 访客网络 | 写入前检查全部目标接口；缺失接口、提交失败、应用失败均返回错误，不静默跳过 |
| 访客访问时限 | API 与界面使用分钟；原厂配置使用秒，读写分别换算。60 分钟对应 3,600 秒 |
| 网络名称与密码 | 保留合法标点，拒绝控制字符；UCI 使用独立命令参数传值，不经过 shell。密码不再被静默删除字符 |
| 自动休眠 | 先校验整份请求，再应用；持久化失败返回错误，写后回读不一致也不报告成功 |
| 状态未知 | Wi-Fi 标准、自动休眠和快速开机读不到状态时，不以关闭值替代 |
| 机身共用设置流程 | 保存错误不会被“已重新读取”覆盖；读回失败时同时保留原始操作错误。Wi-Fi 密码也纳入自动保存的回读核对，验证后编辑框保持空白 |

无线写入串行处理，先检查全部字段、类型和目标配置节。原厂重载在慢请求通道等待，最多观察 60 秒；Web 和屏幕的无线设置请求允许 90 秒，避免占用常规状态读取的通道；只轮询读取，不重复应用指令。确认包含原厂重载结束与请求字段回读一致，无法确认时提示重新检查实际状态。B31 样机一次标准切换约 16 秒；此耗时只供参考，不是固定时限。

## 验证范围

代码检查覆盖机身共用自动保存流程、Wi-Fi／访客设置，以及休眠、快速开机和电源等相邻设置的读写路径。其他网络与组网设置仍沿用各自的冲突检查和回读流程；这不代表所有后台接口都做过真实设备改写测试。

自动回归覆盖缺少可选开关、两频段无线标准切换、标点密码保真、发射功率原厂接口、访客分钟换算、目标接口缺失、写入／提交／重载失败，以及应用后值不一致。Web 验证全局标准切换后关联控件立即更新、取消无写入、重新打开页面后的已保存值；机身验证真实错误保留与密码回读。

软件检查：完整后台回归 1,172 项通过、8 项忽略；随后新增原厂重载暂不可读测试，无线相关 18 项全部通过。机身 48 项功能相关测试及客户端 HTTP 测试通过；Web 3 项单元测试、生产产物浏览器回归与共享 Wi-Fi 输入校验通过。密码标点保真通过自动测试验证，不以此宣称所有原厂版本都已实测。

- 关闭 Wi-Fi 7 用时 16.77 秒，再开启用时 16.72 秒；两次请求均返回核对成功。独立读取 `/etc/config/wireless` 确认开关与两频段模式已持久化，带宽恢复为 EHT40／EHT160。
