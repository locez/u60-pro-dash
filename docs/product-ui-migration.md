实施依据为 `design/product-ui/DESIGN.md`，实现分支为 `feat/product-ui`。
Web 使用 React、Tailwind 和 Vite，资源压缩后嵌入后台；设备屏幕继续使用 Rust 与 Slint。

## 交互与运行约束

普通设置在选择选项、回车或离开输入框时提交；缺少必要字段时保留草稿。只有会中断连接或需要停服务的修改才提示影响。用户取消后保留原值，校验或回读失败显示错误，写入超时不自动重试。

长配置的“完成编辑”执行校验、保存和热重载。服务停止时只保存。浏览器会话内切页保留未完成的配置草稿，退出会话清理；读取当前配置覆盖草稿前需确认。

页面隐藏、注销和离开对象后停止不再需要的订阅或轮询；短信正文、日志和编辑器不由后台更新重建。图表保留有限采样窗口，数据缺失留空，不编造零值。扫描、测速、检测和检查更新仍由用户主动启动。

各服务可以共存，显示偏好不控制进程启停。Tailscale 的 DNS 与出口节点仅在内核网关模式提供；这些偏好作用于路由器，热点转发仍遵循已有配置的远端网段，不将节点在线误报为目标服务可达。

屏幕外观和首页布局使用同一份偏好，由 Web 和机身共享；写入采用字段合并与原子替换。PIN 校验和密码存储保留在原生安全流程内，外观接口不能读写它们。

屏幕材质为缓存的静态明暗层次、细边缘与弱透明，无持续背景模糊。保持按变化区域绘制、熄屏停止无用采样。固件没有系统主题来源时，“跟随系统”明确回落到已有固定主题。

## 已知边界

- 固件不提供统一配置备份接口，页面明确说明本地备份方式，不提供无效的备份按钮。
- 项目升级继续使用成套部署脚本，Web 不调用仅更新后台的旧 OTA 流程。
- 证书由设备已有 HTTPS 能力生成、续期和重置；不新增任意证书导入。
- Web 提供停用状态的每日重启任务创建、任务启停和删除；完整的自定义计划及恢复动作保留在机身的计划任务页面。
- SIM／eSIM、通话、网络锁等依赖卡片与固件。自动设备验收不执行 PIN 尝试、套餐下载或可能计费的操作。
- 触摸、长短信滚动、锁屏和配色已通过软件渲染与输入回归；本轮部署后的机身主观观感仍需实际使用确认。短时 CPU 观测不能代替续航测试。

## 构建与访问

开发主机需 Node.js 22.12 以上。首次执行 `cd u60-web && npm ci`，再执行 `npm run build`；设备无需 Node.js。直接运行 Cargo 前必须先构建前端，Rust 构建脚本会拒绝源码摘要不匹配的过期页面。

仓库根目录执行 `bash dash.sh build --offline` 构建两个程序；`bash dash.sh check` 检查设备，`bash dash.sh install --no-build` 部署已校验产物。产物在 `target/dash/`，`bash dash.sh rollback` 恢复上一组程序。

浏览器回归：在 `u60-web/` 执行 `npx playwright install chromium`，生产构建后运行 `npm run test:browser`。已有 Chrome 的主机可设置 `U60_TEST_BROWSER_CHANNEL=chrome`。测试使用模拟接口，不调用设备写接口。

管理端口保持 2026，入口 `/console/`。旧书签映射到新分类。HTML 每次重新验证，带内容摘要的脚本、样式和字体长期缓存。

旧界面的暂缓改动仍保留在原工作区文件中，没有并入本次提交。
