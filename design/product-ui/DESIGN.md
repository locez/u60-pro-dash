# U60 产品界面设计 · 第二阶段

## 已确认的方向

Web 使用克制专业的 A 方向：浅色为默认，低饱和蓝灰，统一表格、状态与表单。深色沿用相同的信息层级。设备屏幕使用紧凑高密度的 C 方向：320 × 480，关键数字突出，固定底部导航，按对象进入详情。

共享的是名称、功能归属和状态语义。Web 有空间处理长配置、表格与多步操作；屏幕优先显示状态与常用短操作，两端不机械复制同一布局。

## Web 导航

| 一级入口   | 页面内容                                                | 归属原则                           |
| ---------- | ------------------------------------------------------- | ---------------------------------- |
| 概览       | 连接拓扑、速率趋势、套餐、电量、设备与服务摘要          | 显示结果，并进入对应对象           |
| Wi-Fi      | 热点设置、访客网络、无线参数、分享连接码                | 无线广播与连接凭据                 |
| 连接设备   | 在线设备、历史设备、单设备状态与访问权限                | 按客户端查看和管理                 |
| 移动网络   | 信号与频段、连接设置、SIM 与 eSIM、流量套餐、运营商服务 | 与蜂窝链路和 SIM 相关的能力        |
| 短信       | 收件箱、写信、转发规则与记录、存储管理                  | 完整消息生命周期                   |
| 组网与服务 | 服务列表 → 各服务详情                                   | 每个服务拥有自己的配置、日志与维护 |
| 局域网     | LAN 与 DHCP、DNS、访问控制与转发                        | 本地地址、解析与网络策略           |
| 系统设置   | 电源与电池、屏幕与安全、更新与备份、诊断工具、自动化    | 设备本身的维护与运行方式           |

Tailscale 的连接与登录、接受路由、热点访问子网、DNS、退出节点、检测与更新都在同一个服务内。WireGuard 管理自己的隧道与对端。代理服务按实际引擎呈现原生配置与能力，不设计通用配置表单去压平不同引擎的差异。

服务独立运行。列表中的开关只影响对应服务，不做全局互斥选择；冲突应报告具体监听端口或路由，再处理该冲突。

## 屏幕导航

| 主入口 | 常用内容                                                          | 深层内容                                           |
| ------ | ----------------------------------------------------------------- | -------------------------------------------------- |
| 状态   | 运营商与信号、上下行、设备数、套餐、电量与供电、连接码、服务摘要  | 流量趋势、套餐详情                                 |
| 连接   | Wi-Fi、连接设备、移动网络、SIM 卡、Tailscale、WireGuard、代理服务 | 对应对象的状态、常用设置与维护                     |
| 管理   | 短信、电源与电池、屏幕与安全、诊断工具、设备设置                  | 更新备份、管理访问、计划任务、运营商工具、高级网络 |

常用操作优先保持浅层路径。列表和正文各有滚动容器，底部导航不进入正文滚动范围。进入详情回到顶部，后台数值更新保留当前阅读位置。

首页使用固定结构内的可选模块。运营商、上下行与顶部状态保持稳定；信号详情、Wi-Fi 连接卡片和组网服务摘要可独立隐藏，摘要内的服务也可分别选择。三格快捷指标可更换内容、交换位置或隐藏，剩余项自动等宽排列，不留下空占位。显示偏好与服务启停独立存储，隐藏服务不会停止进程或删除管理入口。

屏幕浅色与深色覆盖所有页面和控件，并支持跟随系统；主题、强调色与首页布局互相独立。原型用浏览器配色偏好演示“跟随系统”，设备实现时应使用设备实际的系统主题来源；若固件没有该来源，明确回落到固定主题，不能暗示设备具备自动明暗传感器。自定义色的文字按背景调整明度，按钮前景单独计算对比度。

屏幕的配置摘要中，只要是短操作就直接提供编辑入口。运行模式与流量范围必须可点选，选项标明当前值。支持热更新的运行模式选完即生效，不再确认；流量范围或监听端口只有在运行中确实需要停服务时才提示中断影响，确认后自动完成停止、应用与恢复运行。服务已停止时直接保存，不擅自启动。写入完成后回读实际值。保存失败保持原值并显示可处理的错误，不显示成功。流量范围变更还需验证路由规则与管理连接；长 YAML 和密钥编辑可转到 Web，但不以此替代这些短设置的设备端操作。

连接二维码在各卡片内固定尺寸。网络名称与密码在旁边独立换行；双频同名同密码使用一张连接码，设置不同时分别提供。显示密码直接替换原掩码所在位置。

锁屏显示运营商、网络、速率、设备数、电量与供电状态，隐藏二维码、密码与管理操作。长按 1 秒只承担防误触；开启 PIN 后，长按转入 PIN 校验。浏览器原型使用固定的演示 PIN，正式版必须沿用现有设备安全存储与校验机制。

## 状态与操作约定

1. **连接状态分层。** 本地管理可用、蜂窝联网、服务进程运行、远端节点在线、目标 TCP 可达分别表达，不能用某一层的成功代替另一层。
2. **普通设置修改即应用。** 开关、选项、外观与布局不设第二次保存；文字输入在回车、软键盘“完成”或离开输入框时提交，先检查完整性。只在确实需要停止／重启服务或会中断管理连接时提示具体影响；取消保留原值。界面应显示正在应用、已生效或错误，不把尚未成功的修改显示成已生效。
3. **长配置完成后一次应用。** YAML 编辑器以“完成编辑”结束一次完整输入，自动执行校验、保存与热重载，无须再点第二个应用按钮。服务停止时保存供下次启动使用。失败保留编辑内容与上一个有效配置，标明失败环节；不能用保存成功代替运行成功。校验、扫描和检测仍可作为主动工具。
4. **能力不足是正常状态。** 普通 SIM 显示不具备下载配置能力；可管理 eUICC 卡才展示配置列表与下载入口。接口故障要单独显示错误。
5. **刷新按内容决定。** 状态数字增量更新；图表只追加点；短信、配置编辑、已加载的日志不被轮询重置。扫描、测速、检测、检查更新保留主动按钮。
6. **维护操作有对象。** 服务安装与更新在对应服务内；项目发布更新覆盖后台与屏幕两个进程；“当前进程”是观察入口，结束进程是独立操作。

## 视觉与功耗

- Web 用留白组织区域，表单每组只表达一个主题，图表和表格承担比较任务。主操作用蓝色，正常状态用低饱和绿色；颜色不单独承担含义。
- 原生屏幕实现时增加轻量毛玻璃质感，设计稿不追加此效果。以弱透明、细边缘和静态明暗层次表现材质，保留强调色；浅深主题都要保证小字对比度。优先缓存静态合成结果、按变化区域更新，不采用持续背景模糊、液态折射或常驻动画；实机检查功耗和帧耗时，不能为材质牺牲续航与文字清晰度。读数和标签分级，避免把全部信息做成同等粗细的一行。
- 屏幕强调色沿用原生界面的六种预设与自定义色，覆盖重点读数、趋势线、当前导航、主按钮和解锁提示。颜色填充保留用户选择，文字与按钮前景单独保证对比度；正常、充电、警告和错误不混用主题色。切色即时生效，不添加屏幕过渡动画。
- 图表是固定历史窗口。原型使用本地 SVG；原生实现应限制点数，只在数据变化时更新可见区域，并在熄屏时停止无用采样与绘制。
- 浏览器原型没有设备轮询或常驻动画。实际 Slint 字体、像素对齐和触点仍需在设备上验证。

## 本轮覆盖与边界

[features.json](src/features.json) 与 `u60-screen/assets/catalog.json` 的 82 个功能 ID 一一对应，没有新增或删除硬件能力。功能地图用于审核导航迁移，不能用来统计已接入的后台接口数量。

已展开的交互设计覆盖 8 个主分类及 38 个页面／子页视图，包括 Wi-Fi 编辑与分享、设备表、信号与连接设置、SIM 能力状态、套餐、服务详情、日志、安装更新入口、配置自动保存与重载、短信、电源、系统维护和诊断。

低频高级操作仍有需要细化的部分：精细小区锁定和 STC、SIM PIN／PUK 完整状态、网络锁、证书导入校验、完整转发规则编辑、备份恢复差异、AT 会话、通话与 SIM 工具菜单。当前原型为这些功能安排入口或展示基础流程，后续接入时必须根据真实字段与能力完善。

屏幕原型已展开主要状态页、连接列表、服务详情、路由与检测、供电、长短信和锁屏。部分长配置使用 Web 管理地址说明作为占位，不代表最终取消设备端已有功能；最终迁移要逐项核对现有入口再决定完整表单或配套编辑方式。

语言菜单目前用于评审位置与设置流程，正文尚未完成全部语言。正式实现需接入现有语言资源，并为运营商、状态枚举、错误和动态名称设计一致的本地化规则。

## 接入次序

1. 固定导航、页面组件、状态与错误模型；将真实 API 数据适配为 UI 使用的稳定对象。
2. 接入概览、Wi-Fi、设备与移动网络，先验证真实读数和配置回读；写入前完成有效性检查，按实际中断能力决定是否提示。
3. 按服务逐个接入配置、日志、更新和故障恢复，保留服务共存及端口／路由冲突的可见反馈。
4. 接入短信、系统维护与诊断，处理取消、超时、部分失败和长内容阅读状态。
5. 在 Rust + Slint 中落地新分类与视觉，复用已有设备能力；验证 320 × 480、字体、触摸、熄屏、锁屏与低功耗行为。
6. 对照 82 项功能地图验收，再进入成套构建、候选版本试运行与回滚验证。

设计预览与现有设备程序分离，当前提交不会改变管理端口或设备部署产物。
